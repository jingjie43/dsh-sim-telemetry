## 二、项目背景

跑赛车游戏时，玩家普遍面对同一个问题：**知道自己慢，但说不清慢在哪。**

游戏只提供一个圈速数字，不告诉你：
- 是哪个弯慢了？
- 是刹车点早了、还是出弯给油晚了？
- 是入弯速度不够、还是走线不对？

市面上的专业遥测软件（如 Motec）门槛高、界面复杂、需要自己读曲线；而"开得快"的经验又很难靠文字传授。

本项目要解决的就是这个断层：**把游戏遥测变成"人话"**，让 AI 直接告诉你这一圈差在哪、该改什么。

## 三、项目目标

### 短期目标（V1，已完成）
- 打通 F1 25 的 UDP 遥测采集
- 自动切圈、圈速、分段、弯道识别
- 输出人类可读的分析结论
- 做成可安装、可配置的 DSH 插件

### 长期目标
- 兼容市面主流赛车游戏（神力科莎竞速、神力科莎、其他大众赛车）
- 从"自己跟自己比"进化到"跟 AI 车手比"
- 成为"跑完自动出报告"的赛车训练助手

## 四、功能范围

### 已完成（v0.2.1）
- F1 25 UDP 遥测采集（端口 20777，可配置），玩家 + 全部 22 辆车
- 自动切圈、圈速、分段
- 弯道识别（刹车点锚定 + 速度谷补充）
- 输出三件套：文字摘要 / CSV 表格 / 完整明细 md
- 速度曲线图、油门刹车图
- 「跑到第 N 圈自动出报告」：跑满自动停、自动生成
- 设置面板：启用开关、默认时长、自动报告圈数、UDP 端口、Python 路径
- Python 自动探测（≥3.10）+ 一键安装 Python / Pillow
- 回退（flashback）检测：回退造成的重复时间不计入成绩

### 规划中
- **AI 车手对比**：AI 在每个弯的速度、圈速对比
- **每弯明细表**：入弯 / apex / 出弯 / 刹点
- **20 段速度表** + 时间损失估算
- **面板实时状态**：已采圈数、当前速度
- **多游戏适配器**：ACC、AC、Forza 等

## 五、技术方案

### 总体架构

```
┌─────────────────────────────────────────┐
│  插件层（Node.js）                        │
│  · 4 个工具：telemetry_start/stop/        │
│    summary/plot                          │
│  · 设置面板 + HTTP 路由                   │
├─────────────────────────────────────────┤
│  采集层（Python，每个游戏一个适配器）       │
│  · collect_f1.py（F1 25 UDP）            │
│  · 未来：collect_acc.py / collect_ac.py  │
├─────────────────────────────────────────┤
│  分析层（Python，所有游戏共用）             │
│  · summary.py：切圈/分段/弯道/摘要/CSV    │
│  · plot.py：速度曲线/油门刹车图            │
├─────────────────────────────────────────┤
│  数据层（本地文件）                        │
│  · ~/.dsh/sim-telemetry/*.jsonl           │
│  · laps_*.csv / summary_full_*.md         │
└─────────────────────────────────────────┘
```

### 关键设计决策

1. **采集与分析分离**：加新游戏 = 加一个采集适配器，分析管线全部复用
2. **本地计算**：所有分析在本地 Python 完成，AI 只读结论 → 省 token、数据不出本机
3. **按需启动**：不跑车时不监听，插件只是壳
4. **原始数据落盘**：可反复分析，不丢历史

## 六、与现有方案的差异

| 维度 | 普通遥测软件（如 Motec） | 本项目 |
|---|---|---|
| 输出形式 | 一堆曲线，自己读 | **直接给结论**：「这个弯该敢带油」 |
| 使用门槛 | 需要懂遥测分析 | 跑完就能看 |
| 数据位置 | 本地/导出文件 | **本地**，不上传 |
| 智能程度 | 无 | AI 翻译成人类可读建议 |
| 游戏覆盖 | 单游戏为主 | **架构支持多游戏**（逐步接入） |
| 成本 | 免费/付费软件 | 开源免费 |

核心差异一句话：**它不做"数据展示"，它做"数据翻译"。**

## 七、风险与不足（诚实评估）

### 当前欠缺
1. **只支持 F1 25**：其他游戏需要单独写适配器
2. **弯道没有真实名称**：按速度曲线自动识别，只能叫「弯 1」「弯 2」
3. **逐弯对比是近似**：遥测不含位置数据，按速度谷对齐，不是精确对齐
4. **AI 对比未完成**：目前只能自己跟自己比
5. **界面简陋**：只有开关和几个按钮
6. **依赖 Python 环境**：对纯小白有一定门槛

### 技术风险
- 各游戏遥测格式差异大，适配器开发成本不完全可控
- F1 系列每年更新包格式，需要跟进维护
- 部分平台（如 PS 系）不开放遥测，无法支持

### 规避思路
- 适配器逐个接入，先做验证过的
- 保留原始数据落盘，格式变了也能用旧数据重算
- 明确写在 README 里的支持范围，不夸大

## 九、资源与成本

- **开发成本**：个人业余时间，无外部投入
- **运行成本**：本地运行，无服务器费用；AI 调用按 token 计费，但单轮分析仅几百 token
- **维护成本**：游戏版本更新时跟进包格式

## 十、结论

本项目以"**把遥测数据翻译成人话**"为核心价值，已完成 F1 25 的首个可用版本并开源。
